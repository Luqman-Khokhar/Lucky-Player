# run-app — Lucky Player development

## Project facts

- Offline Android video player. Expo SDK 57, React Native 0.86, TypeScript, expo-router, Redux Toolkit,
  expo-sqlite. Android only.
- Development build, not Expo Go: playback uses the local native module `modules/vlc-player`
  (Kotlin, libVLC 3.7.6).
- `android/` is generated by `npx expo prebuild` and git-ignored. Never hand-edit it; change
  `app.json`, config plugins, or `modules/vlc-player` instead.
- Test phone: Infinix X6880, MediaTek MT6789 (Helio G99), Android 15 (XOS 15), arm64-v8a, 120 Hz.
- Port 8081 on the dev machine is used by another project. Metro runs on **8082**, and the phone's
  8081 is forwarded to it with `adb reverse`.

## JS change or native change?

| Changed | Action |
|---|---|
| Files under `src/` (TS/TSX) | Nothing to rebuild; Fast Refresh applies it. Press `r` in Metro if it does not. |
| `modules/vlc-player/android/**`, `app.json`, config plugins, native dependencies | Rebuild and reinstall the APK (below). |
| New config plugin or `app.json` native fields | `npx expo prebuild --platform android` first, then rebuild. |

## Build, install, run

```bash
# 1. Debug APK, arm64 only (the phone's ABI; fastest)
cd ~/kam/Player/android
./gradlew :app:assembleDebug -PreactNativeArchitectures=arm64-v8a
adb install -r app/build/outputs/apk/debug/app-debug.apk

# 2. Metro, from the project root (not from android/)
cd ~/kam/Player
npx expo start --port 8082            # add --clear after moving routes or changing babel/metro config

# 3. Connect and launch
adb devices                            # phone must show "device"
adb reverse tcp:8081 tcp:8082
adb shell am start -n com.kam.player/.MainActivity
```

## Checks before handing work back

```bash
cd ~/kam/Player && npx tsc --noEmit
cd ~/kam/Player/android && ./gradlew :app:compileDebugKotlin -PreactNativeArchitectures=arm64-v8a
```

## Logs and debugging

```bash
adb logcat | grep -E "ReactNativeJS|VLC|AndroidRuntime"         # live
adb logcat -d | grep -A20 "FATAL EXCEPTION"                      # Java/Kotlin crash
adb logcat -b crash -d | tail -40                                # native crash buffer
adb shell dumpsys dropbox --print data_app_anr | grep -A30 '^"main"'   # freeze (ANR): main thread stack
```

No `FATAL EXCEPTION` but the app died? Check for `ANR in com.kam.player` in logcat; the dropbox
stack shows exactly which call blocked the main thread.

## Lessons already paid for

- **libVLC calls stay on the `vlc-player` worker thread.** `MediaPlayer.stop()` joins native threads
  that may wait on the main thread; calling it on main froze the app (ANR on the MT6789).
- **React Native does not measure native child views.** `VlcPlayerView.onLayout` sizes the video
  surface explicitly; without it the surface is 0×0 and only audio plays.
- **XOS routes file picks to Google Drive**, which forwards no read grant for local files. Use
  `VlcPlayer.pickVideo()` (DocumentsUI + persisted grant), not `expo-document-picker`.
- **Horizontal ScrollViews in a column** need `flexGrow: 0` or they stretch to fill the height.

## Troubleshooting

| Symptom | Fix |
|---|---|
| "Unable to load script" | `adb reverse tcp:8081 tcp:8082`, then press `r` in Metro |
| `expo start` fails with "package.json does not exist" | Run it from `~/kam/Player`, not `android/` |
| "Port 8081 is being used" | Expected; use `--port 8082` |
| Gradle stuck or locked | `cd android && ./gradlew --stop`, then rebuild |
| Duplicate React key warnings | Sibling elements need distinct keys, e.g. `player-${n}` vs `settings-${n}` |
